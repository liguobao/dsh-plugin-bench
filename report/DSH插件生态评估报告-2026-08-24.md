# DeepSeek Harness（DSH）插件生态评估报告

> 2026-08-24 重跑版。数据来自 GitHub API 一手快照，不使用目录站汇总。

- GitHub topic 官方计数：**11,280**
- 实际去重枚举：**11,272**，覆盖 **99.93%**；运行中新出现的 8 个仓库未进入快照
- README 覆盖：**2,275** 份，包括全部 **778** 个 star ≥ 10 仓库，以及 1,955 个“活跃 × 有星”仓库中的 1,953 个；另 2 个无 README
- 活跃锚点：沿用 v0.1.1-rc.1 的 `2026-08-21T07:12:39Z`；rc.2 仅为图像处理体验优化，不改锚点
- 三桶口径：生态起点 2026-02-01 + DSH-first 文本关联 + 66 个产品优先人工覆盖
- 分发数据窗口：旧核心仓库沿用 2026-08-23 快照，本轮新增仓库补查于 2026-08-24

## 一、结论先行

1. **规模已超过 1.1 万，但近半仍是一次性仓库。** 11,272 个仓库中，5,427 个只在创建当天 push，占 48.1%；0–4★ 共 9,883 个，占 87.7%。仓库数继续增长，没有自动转化成可维护供给。
2. **rc.1 后有 push 的比例升到 31.1%，但不能直接解释为生态健康度大涨。** 3,510 个仓库通过固定锚点，其中包含锚点后新建的一次性项目；更可靠的核心是“有星 × 锚点后活跃”交集，共 1,955 个。
3. **高星层明显变健康，但仍有四成停滞。** star ≥ 10 的 778 个仓库中，458 个通过锚点，320 个未通过；100★+ 跟进率已升到 78.8%。
4. **star 榜依然主要反映独立产品知名度。** README 覆盖集里，87 个适配型独立产品拿走 52.5 万星，占 80%；2,032 个原生仓库只有 10.4 万星，占 15%。第一个原生仓库仍要到总榜第 11 名。
5. **原生生态的血管是 npm，不是 GitHub Release。** 原生活跃桶贡献全部 npm 周下载的 94.1%，却只贡献 Release 下载的 15.9%；Release 榜仍被 PicGo、open-design、BrowserSkill、openpencil 等适配型产品支配。
6. **最大结构性问题从“有没有插件”变成“能不能安装”。** 活跃有星仓库中，726 个已经写了 package name 却从未发布 npm；607 个有 Release 的仓库没有任何附件下载。

| 阶段 | 数量 | 说明 |

本轮并没有把 1,955 个活跃仓库全部重新人工逐行分类。上一轮仍活跃的 **1,128** 个仓库沿用人工标签；新增的 **825** 个按 README 摘要做窄规则增量分类；2 个仅有元数据。`data/active_inventory.json` 中保留 `classification_source`，所以增量分类不应被引用为人工金标准。

锚点也有两个边界：纯皮肤可能不需要适配 rc.1；固定锚点离现在越远，锚点后新建项目越容易自动算“活跃”。因此报告把 `pushed ≥ anchor` 当跟进信号，而不是“仍可正常安装”的证明。

## 九、建议

给使用者：

- 先筛原生、再看 rc.1 跟进、最后看 npm/Release 是否真实可安装；不要从全局 star 榜直接抄答案。
- 桌面、市场、计费、皮肤已经高度同质化，优先选分发成熟、兼容日志清楚的头部。
- Provider/订阅类插件需要额外检查账号安全、服务条款与更新频率。
- Remote 类必须把认证、撤销、隧道信任、明文可见性和自托管能力放在功能之前。

给作者：

- 726 个“有包名但未发布”的仓库是最直接的工程化债务；先把安装链路做完，比再加一个功能更有价值。
- 安全治理、企业权限/审计、自托管中继仍是供给不足的方向。
- 在 README 明确写出支持的 DSH 版本、升级记录和安装渠道，本身就是竞争力。
